# 家づくりメモアプリ — Cursor 引き継ぎ指示書

このファイルをリポジトリの `docs/HANDOFF.md` に置き、Cursor の Composer にそのまま渡す。
既存プロトタイプ（単一HTML）は `legacy/iezukuri-notes.html` として同梱し、**仕様書として参照するが移植はしない**。作り直したほうが速い。

---

## 1. 何を作るか

積水ハウスとの家づくり打ち合わせ用の個人メモアプリ。**スマホで片手操作、打ち合わせ後15分の転記が続くこと**が唯一の成功条件。
ユーザーは1人（＋将来的に妻と共有の可能性）。認証は当面不要。

4つの画面だけ。増やさない。

| 画面 | 性質 | 役割 |
|---|---|---|
| 決定 | 上書き型 | 決まったことの最新状態。確定度と図面反映を追う |
| 質問 | 消込型 | 次回聞くこと。回答が出たら消える |
| アイデア | 溜め込み型 | 判断しない。放り込むだけ |
| 議事録 | 追記型 | 毎回5項目。担当者に送る文面を生成 |

---

## 2. 技術選定

- **Vite + React + TypeScript**
- **Tailwind CSS**（プロトタイプの生CSSは移植せず、下のトークンをTailwind configに入れる）
- 状態管理はライブラリを入れない。`useState` + Context で足りる
- **Vercel** にデプロイ。`manifest.json` を置いて **PWA（ホーム画面に追加）** できるようにする ← スマホ運用の前提

### 保存層（最重要・ここだけ設計を守ること）

プロトタイプは Claude Artifacts の `window.storage` を使っている。**これは外では動かない。**

`src/storage/` に**アダプタ層**を切り、実装を差し替え可能にする：

```ts
export interface Store {
  load(): Promise<AppData>;
  save(data: AppData): Promise<void>;
}
```

- **Phase 1**：`LocalStore`（localStorage、キー `iezukuri-notes:v1`）で完成させる
- **Phase 2**：`SupabaseStore` を追加。呼び出し側は一切変更しない

Phase 1 の時点で **JSONの書き出し／読み込みUI** は必ず実装する。機種変とバックアップの生命線。

## 3. データモデル

```ts
type Status = 0 | 1 | 2 | 3; // 検討中 / 仮 / 確定 / 変更不可

interface Decision {
  id: string;
  cat: string;        // 大分類（下記固定リスト）
  title: string;      // 項目名
  body: string;       // 決定内容
  status: Status;
  drawn: boolean;     // 図面に反映されたか
  area?: string;      // 外構エリア（外観・外構カテゴリのみ）
  cost?: number;      // 万円
  due?: string;       // 変更締切 YYYY-MM-DD
  updatedAt: string;
}

interface Question {
  id: string;
  to: '営業' | '設計' | 'インテリア' | '外構' | '自分で調べる';
  text: string;
  answer: string;
  done: boolean;
}

interface Idea { id: string; text: string; tag: string; url: string; createdAt: string; }

interface Minute {
  id: string; date: string; theme: string;
  decided: string; myTodo: string; theirTodo: string; pending: string; newq: string;
}

interface AppData { decisions: Decision[]; questions: Question[]; ideas: Idea[]; minutes: Minute[]; }
```

**大分類（固定）**
外観 / 外構 / 間取り・寸法 / 窓・サッシ / 空調・給湯 / 電気 / キッチン / 洗面・浴室・トイレ / 収納 / 内装 / 外部設備 / 資金

**外構エリア（`area` の候補）**
道路〜アプローチ / 駐車場 / 前庭40坪 / 東側ウッドデッキ / 建物外観 / サービスヤード / 境界

## 4. 画面仕様

### 共通
- 上部固定ヘッダーに3つの数字：**未確定 / 図面未反映 / 未質問**。ここが打ち合わせ前のダッシュボード
- 下部固定タブバー（4つ）。親指で届く位置に置く
- 一覧のカードはタップで展開してその場で編集。別画面に遷移させない（往復が増えると転記が続かない）

### 決定
- 大分類ごとにグルーピング表示
- 左ボーダーの色で確定度を表現：検討中=グレー / 仮=琥珀 / 確定=緑 / 変更不可=黒
- フィルタチップ：すべて / 未確定 / 図面未反映 / 大分類別
- 展開時：本文編集、確定度の4ボタン、図面反映トグル、削除
- **追加要件（プロトタイプに未実装）**
  - `due`（変更締切）を持たせ、期限が近い・過ぎた行を一覧上部に出す
  - 外構カテゴリのとき `area` セレクトを表示し、エリア別グルーピングに切り替えられる

### 質問
- 未回答を上、回答済を下に折りたたむ
- 展開時に回答を入力 → 回答済トグル
- **追加要件**：回答済の行に「決定台帳へ送る」ボタン。押すと Decision を生成して質問は消える（3つの箱の連結点。ここが効く）

### アイデア
- テキスト＋タグ＋URL のみ
- **追加要件**：写真の添付（`<input type="file">` → Phase 1 は IndexedDB か dataURL、Phase 2 は Supabase Storage）。外構検討では写真が主役になる

### 議事録
- 新規作成：日付／テーマ／5項目（決まったこと・自分の宿題・先方の宿題・保留・新たな疑問）
- 「担当者に送る文面をコピー」→ 整形テキストをクリップボードへ。末尾に「認識違いがあればご指摘ください。」を付ける
- **追加要件**：保存時に「決まったこと」の各行を決定台帳へ、「新たな疑問」の各行を質問リストへ**一括で送るダイアログ**を出す。転記の手間がここでほぼ消える


## 6. 実装タスク（この順で）

1. Vite + React + TS + Tailwind の雛形、トークン設定
2. `Store` インターフェースと `LocalStore`
3. タブ構造とヘッダーの3数字
4. 決定タブ（追加・展開編集・フィルタ）
5. 質問タブ（＋決定台帳への昇格）
6. アイデアタブ
7. 議事録タブ（＋コピー機能）
8. JSON書き出し／読み込み
9. PWA対応、Vercelデプロイ
10. （必要になったら）`SupabaseStore`

---

## 7. やらないこと

- ログイン・ユーザー管理（Phase 2 で共有が必要になるまで不要）
- 通知、リマインド
- 検索機能（フィルタで足りる。項目数はせいぜい200件）
- ダークモード
- アニメーション（開閉以外）

スコープを膨らませるとアプリを作ることが目的になる。**8週間使えれば役目は終わる道具**として作る。
